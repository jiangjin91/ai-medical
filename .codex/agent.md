# AGENT.md

## 项目简介

[一句话] 这是一个由电商智能客服迁移而来的患者端医疗服务助手原型，基于 Vue 3 + Vite、Python + FastAPI 和 LLM 多轮对话/任务编排能力，
目标是帮助患者完成预约、检查检验、报告、复诊与人工服务转接等就医服务任务。

## 技术基线（未经确认不得擅自升级）

- 前端：Vue `3.5.x` + Vite `6.2.x`，ES Module；目录为 `ai-frontend/`。
- AI 服务：Python `>=3.12`、FastAPI、LangChain、SQLAlchemy；目录为 `ai-service/`。
- 业务服务：Python `>=3.11,<3.13`、FastAPI、SQLAlchemy、PyMySQL；目录为 `backend-service/`。
- 依赖管理：Python 服务使用 `uv`；前端使用 npm。
- 开发端口：前端 `5174`；AI 服务从 `ai-service/.env` 的 `app_port` 读取（当前前端代理指向 `18082`）。
- 既有业务服务和部分 AI 知识/流程仍为电商示例。迁移医疗场景时必须替换领域模型、接口语义、提示词、知识和流程配置，禁止仅改页面文案。
- 不修改 `.env`、密钥、Token、证书或 CI/CD 配置；确需修改时先征得用户明确同意。

## 硬性规则（必须遵守）

1. 产品定位是“患者就医服务助手”，不是 AI 医生：不得实现或暗示疾病诊断、处方开具、药物剂量建议、治疗方案推荐或临床分诊结论。
2. 遇到急症、高风险症状、自伤他伤等表述，停止开放式医疗问答；展示规范紧急提示，并引导急诊/120 或转人工。该路径必须由可审计规则触发，不能仅依赖大模型判断。
3. 对患者展示的医疗流程、检查准备、报告说明等内容必须来自经医院审核、可版本化的知识；不得将 LLM 自由生成内容作为医疗事实输出。
4. 仅收集完成当前服务任务所需的最少信息；不在日志、提示词、前端状态或错误信息中输出身份证号、病历、检查报告等敏感数据。
5. 患者身份校验、代办授权、数据查询和人工转接必须保留可追溯的任务/工单记录；接口鉴权和数据权限未设计完成前，不得接入真实医院数据。
6. 业务动作按“查询 → 患者确认 → 执行 → 返回可见结果”设计。预约取消、改期、缴费、投诉等会改变状态的动作，必须明确确认和幂等保护。
7. 任何人工转接必须携带已脱敏的会话摘要、已完成操作、当前卡点和患者已确认的联系方式；患者不应重复描述问题。
8. 电商的订单、物流、退款、商品等概念不得直接暴露到医疗端；应分别重构为就医服务单/预约、检查或配送进度、退费/改期、医院服务项目等明确领域对象。
9. 改动跨服务接口时，先更新接口契约、前端代理及错误状态，再实现调用；不得通过静默兜底掩盖服务不可用。
10. 不删除文件、目录、数据库或 Git 历史；不执行 `git reset --hard`、`git rebase`、`git push`。需要这些操作时先征得用户同意。

## 开发与验证

- 前端开发：在 `ai-frontend/` 执行 `npm run dev`。
- 前端构建：在 `ai-frontend/` 执行 `npm run build`。
- AI 服务启动：在 `ai-service/` 使用项目配置启动 `atguigu.main`；启动前确认 `.env` 已由项目维护者配置，不读取或输出其中的密钥。
- 业务服务启动：在 `backend-service/` 使用 `uv run fastapi dev app/app.py`，或按项目部署配置启动。
- 修改 Vue 组件、组合式逻辑或接口封装后，至少运行前端构建验证。
- 修改 Python 服务后，至少执行受影响模块的导入/测试验证；新增核心流程必须覆盖正常、缺少必要信息、服务失败、转人工和紧急安全路径。
- 调试输出使用结构化日志，不使用 `print` 写入患者数据；异常对患者显示可理解的下一步，对内部保留不含敏感信息的诊断上下文。

## 代码与交互约定

- 前端以“任务优先、对话辅助”为主：首页优先展示当前待办、状态和下一步行动；聊天窗口用于解释、补充信息和发起任务，不应成为唯一入口。
- 医疗领域类型、接口字段、流程节点和组件命名使用明确英文业务名，例如 `appointment`、`exam`、`report`、`handoff`；避免继续使用含义模糊的 `order` 或 `logistics`。
- 一个组件只负责一个可识别的患者任务；接口层集中在 `src/api/`，页面/组件不得散落硬编码 URL。
- FastAPI 请求与响应均使用 Pydantic 模型定义；返回数据采用稳定的错误码、患者可读提示和可选的下一步操作。
- LLM 只用于意图理解、对话组织和已审核知识的表达；确定性查询、权限校验、状态流转和安全拦截由代码/规则引擎负责。
- 流程配置、知识内容和提示词的变更要可审查、可回滚，并标识适用院区/科室、版本和审核状态。
