# 人工转接设计

<!-- 本文作用：定义自动客服无法解决时，如何把患者平滑转给合适的人工角色，并减少重复描述。 -->

## 当前 MD 的作用

本文件用于设计转人工体验、分流规则、上下文摘要和处理状态。它重点解决患者“说了一遍又一遍”的问题。

## 转接对象

| 对象 | 适合处理的问题 |
| --- | --- |
| 导诊/门诊服务台 | 就诊流程、地点、窗口、排队咨询 |
| 互联网医院客服 | 线上问诊、账户、订单化服务流程 |
| 护士或专科随访人员 | 术后/诊后随访、护理宣教、复诊提醒 |
| 药师 | 用药咨询的人工入口，不由 AI 给剂量建议 |
| 患者关系部门 | 投诉、纠纷、服务体验问题 |
| 信息科/系统客服 | 登录、报告打不开、支付异常等技术问题 |

## 触发条件

1. 患者主动要求人工。
2. 自动流程连续失败。
3. 触发医疗安全边界。
4. 外部系统不可用且影响患者下一步。
5. 患者问题涉及投诉、纠纷或高情绪压力。

## 上下文摘要

转人工时应传递脱敏摘要：

```text
患者问题：想查询检查报告为什么还没出
身份状态：已验证
已查询信息：检查已完成，报告状态未出
失败原因：LIS 返回预计时间为空
建议队列：检查检验客服
风险等级：低
```

## 患者端体验

1. 明确告知已转接给谁。
2. 展示排队状态或预计反馈方式。
3. 保留会话记录和当前任务卡。
4. 人工回复后可回到自动流程继续完成任务。
