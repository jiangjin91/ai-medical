# 检查检验闭环设计

<!-- 本文作用：定义建议 MVP 场景“检查检验全流程”的患者体验、业务状态和系统动作。 -->

## 当前 MD 的作用

本文件用于细化首发场景。它回答患者从“医生开检查”到“完成检查、获取报告、回到医生处”的过程中，系统如何提供连续服务。

## 场景范围

1. 检查检验预约状态查询。
2. 检查前准备说明。
3. 院内地点和时间提醒。
4. 报告出具状态查询。
5. 报告已出后的复诊或咨询入口。
6. 异常情况转人工。

## 状态模型

| 状态 | 患者端展示 | 可用动作 |
| --- | --- | --- |
| `ordered` | 医生已开具检查 | 查看项目、准备说明、缴费 |
| `paid` | 已缴费待预约或待检查 | 预约、查看地点、设置提醒 |
| `scheduled` | 已预约 | 查看时间地点、改约、取消 |
| `checked_in` | 已签到或已到检 | 查看排队或等待提示 |
| `completed` | 检查已完成 | 查看报告预计时间 |
| `reported` | 报告已出 | 查看报告入口、复诊入口 |
| `exception` | 状态异常 | 转人工处理 |

## 安全边界

1. 系统可以告诉患者报告是否已出、在哪里看。
2. 系统不能解释指标异常代表什么。
3. 系统可以提示“建议按医嘱复诊或咨询医生”。
4. 系统不能根据报告内容生成诊断或治疗建议。
