# 命名规范

<!-- 本文作用：定义医疗化改造中的领域命名，避免继续沿用电商客服项目里的订单、商品、物流等概念。 -->

## 当前 MD 的作用

本文件用于指导变量、接口、组件、任务类型和文案命名。新增医疗功能时，应优先使用这里的词汇表。

## 领域命名

| 推荐命名 | 含义 | 避免使用 |
| --- | --- | --- |
| `appointment` | 预约、挂号 | `order` |
| `visit` | 就诊记录或就诊流程 | `trade` |
| `exam` | 检查项目 | `product` |
| `labTest` | 检验项目 | `sku` |
| `report` | 检查检验报告 | `logistics` |
| `payment` | 医疗缴费 | `checkout` |
| `refund` | 医疗退费 | 可保留，但必须指医疗退费 |
| `handoff` | 人工转接 | `afterSale` |
| `patientTask` | 患者待办任务 | `ticket` 可用于工单，不用于患者任务 |

## 组件命名

1. 患者端页面组件使用 `Patient` 前缀。
2. 医疗任务卡使用 `Card` 后缀，例如 `ExamReportCard`。
3. 对话抽屉、转接面板等交互容器使用 `Drawer`、`Panel` 后缀。
4. 不在新组件中出现 `commerce`、`mall`、`goods`、`shipping` 等电商词。

## 接口命名

1. 患者端 API 统一使用 `/patient`、`/medical`、`/service` 等医疗语义。
2. 外部医院系统适配接口用 `adapter` 或 `gateway` 表达，避免直接暴露 HIS/LIS/PACS 细节给前端。
3. 有副作用的接口命名必须体现动作，例如 `confirmAppointment`、`cancelAppointment`。
