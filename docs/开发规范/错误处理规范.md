# 错误处理规范

<!-- 本文作用：定义患者端医疗服务助手的异常分类、前端提示原则和后端错误码使用方式。 -->

## 当前 MD 的作用

本文件用于保证错误处理一致：患者看到的是可理解、可行动的提示，开发和客服看到的是可追踪、可排障的错误信息。

## 错误分类

| 类型 | 示例 | 患者端处理 |
| --- | --- | --- |
| 身份未验证 | 未登录、授权过期 | 引导重新认证 |
| 权限不足 | 查询他人报告但未授权 | 说明需本人或授权代办 |
| 业务不可用 | HIS、LIS、PACS 暂时不可用 | 告知稍后重试并提供人工入口 |
| 数据不存在 | 未找到预约或报告 | 提示核对信息，不暴露系统细节 |
| 高风险表达 | 急症、自伤、严重症状 | 展示急诊/120/人工指引 |
| 系统异常 | 服务超时、未知错误 | 给出兜底提示和追踪编号 |

## 提示原则

1. 不把堆栈、SQL、第三方接口原始错误展示给患者。
2. 每条错误提示都要告诉患者“现在能做什么”。
3. 涉及隐私和授权失败时，不暗示是否存在某条病历或报告。
4. 转人工时携带错误码、追踪编号和已完成步骤，减少患者重复描述。

## 错误码维护

统一错误码写入 `参考资料/错误码参考.md`。新增错误码时必须同时补充患者端提示、内部说明和推荐处理方式。
