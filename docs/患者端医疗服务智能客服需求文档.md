# 患者端医疗服务智能客服需求文档

<!-- 本文作用：定义患者端医疗服务智能客服的业务目标、应用场景、功能范围、医疗安全边界和 MVP 验收标准。 -->

## 当前 MD 的作用

本文件是项目需求基线，用于回答“为什么做、为谁做、先做什么、不做什么”。后续架构、接口、页面和开发计划都应以本文为上游依据。

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 草案，待业务与医院信息部门确认 |
| 目标用户 | 医院/互联网医院的就诊患者及代办人 |
| 产品定位 | 面向患者的就医任务助手，不提供诊断、处方或治疗决策 |
| 建议首发场景 | 检查检验全流程服务 |

## 1. 背景与问题

患者在就诊前、中、后经常需要重复确认：该挂什么号、检查如何准备、检查在哪里做、报告什么时候出、下一步是否需要复诊。现有医院服务入口通常按系统功能组织，患者需要在挂号、缴费、报告、咨询等多个页面间切换，也常需要向人工重复描述问题。

本项目利用现有的多轮对话、任务状态机、知识问答和人工转接能力，将患者咨询转为可执行、可追踪的就医任务。产品优先解决流程信息不清、人工咨询重复和诊后服务断裂，不承担临床诊疗职责。

## 2. 产品目标

### 2.1 业务目标

1. 降低预约、检查准备、报告状态、复诊指引等高频问题的人工咨询量。
2. 让患者在每一个就医节点明确“当前状态、下一步、需要准备什么”。
3. 在需要人工处理时一次性交接完整上下文，减少患者重复描述。
4. 建立诊前—诊中—诊后的连续服务入口。

### 2.2 用户体验目标

1. 患者进入首页后可在 10 秒内看到当前待办事项。
2. 患者可在任务卡内直接完成常用操作，不必先输入问题。
3. 对无法自动解决的问题，清晰告知处理渠道、转接对象和预计反馈方式。
4. 对高风险或紧急表述不做开放式医疗建议，立即展示规范提示与人工/急诊指引。

## 3. 角色与边界

| 角色 | 职责 | 可见范围 |
| --- | --- | --- |
| 患者/代办人 | 查询并完成本人或被授权就诊人的服务任务 | 经授权的预约、检查、报告状态和服务记录 |
| 智能助手 | 流程引导、状态查询、审核后知识说明、创建转人工请求 | 当前任务和必要的最小化患者上下文 |
| 门诊服务人员 | 处理预约、缴费、导航、检查地点等服务问题 | 所属机构和职责范围内的工单上下文 |
| 专科护士/随访人员 | 处理检查准备、康复、随访等专科服务问题 | 经授权的专科服务上下文 |
| 药师 | 处理用药服务咨询和药品配送问题 | 必要的药品和服务上下文 |
| 患者关系人员 | 处理投诉、纠纷和服务异常 | 投诉工单及相关服务记录 |

### 3.1 明确不在范围内

- 疾病诊断、分诊结论、处方开具、药物剂量建议、治疗方案推荐。
- 对检查报告作出疾病结论；仅可说明报告状态、已审核的字段释义和复诊流程。
- 紧急医疗救助替代；系统仅提供紧急提示与线下急诊/急救指引。

## 4. 大体框架

```text
患者入口（微信小程序 / 医院 App / H5 / 自助终端）
    ↓
患者任务中心（待办卡、进度、通知） + 对话助手（咨询与引导）
    ↓
任务编排服务（状态机、规则分流、人工工单）
    ↓
医院业务系统适配层（预约、收费、HIS、LIS、RIS、药品配送）
    ↓
人工服务工作台（门诊服务、护士、药师、患者关系）
```

### 4.1 交互原则

1. **任务优先，对话辅助**：首页首先展示“需要处理的事”，聊天用于查找、解释和补充。
2. **上下文自动带入**：已登录患者不重复填写患者编号、预约号或检查号；需要切换就诊人时明确确认。
3. **一步一结果**：每次操作均反馈当前状态和下一步，不使用“请耐心等待”等无效答复。
4. **人工接管不断档**：转接时将问题、会话摘要、任务编号、已完成步骤和转接原因一并提交。
5. **安全优先**：医疗知识仅从审核知识库获取；高风险词命中时停止生成式回答并执行固定升级流程。

## 5. 应用场景与功能需求

### 5.1 场景一：诊前服务

| 功能 | 患者价值 | 关键要求 |
| --- | --- | --- |
| 预约与改约 | 快速获知预约时间、地点和状态 | 支持查看、取消、改约；失败时创建门诊服务工单 |
| 就诊准备 | 明确携带资料、空腹/停药等要求 | 内容按检查项目、院区、患者人群展示，来源可追溯 |
| 院内导航 | 减少寻找科室和检查室的时间 | 提供院区、楼栋、楼层、窗口/检查室和到达提示 |
| 费用与支付说明 | 减少缴费相关咨询 | 仅展示授权范围内的待缴项目和支付状态 |

### 5.2 场景二：检查检验全流程（建议 MVP）

| 阶段 | 患者任务 | 系统能力 |
| --- | --- | --- |
| 检查前 | 查看预约、准备事项、地点与时间 | 生成待办卡、发送提醒、回答流程问题 |
| 到院后 | 确认签到/排队状态 | 查询状态；状态异常转门诊服务人员 |
| 检查后 | 查看报告预计时间和出具状态 | 主动通知报告已出；不自动解释医学结论 |
| 报告出具后 | 获取报告、了解后续安排 | 提供报告入口、复诊/取号指引；需医学解释时转对应人工渠道 |

### 5.3 场景三：诊后与连续服务

| 功能 | 关键要求 |
| --- | --- |
| 复诊提醒 | 基于已确认的复诊计划提醒，支持一键进入预约流程 |
| 慢病随访 | 按机构已配置的随访量表收集信息；异常结果由规则升级至人工 |
| 用药与康复宣教 | 仅输出审核过的患者教育内容，不生成个性化剂量或治疗建议 |
| 药品配送状态 | 查询配送状态、地址确认和异常工单；与处方审核解耦 |

### 5.4 场景四：人工转接与异常处理

系统按意图和风险自动选择转接队列：

| 触发条件 | 转接对象 | 必须携带的信息 |
| --- | --- | --- |
| 预约、缴费、地点、检查状态异常 | 门诊服务中心 | 患者/代办身份、预约或检查编号、当前状态、问题摘要 |
| 检查准备、专科随访、护理服务 | 专科护士/随访团队 | 科室、检查项目、已阅读的指引、问题摘要 |
| 药品服务与不良反应描述 | 药师 | 药品名称、服务单/处方关联信息、描述内容 |
| 投诉、服务纠纷 | 患者关系部门 | 相关服务记录/就诊任务、会话摘要、投诉类别 |
| 急症或高风险词 | 固定紧急提示与指定人工通道 | 命中规则、时间、已展示的提示；不得排队等待普通客服 |

## 6. 核心用户流程

### 6.1 检查检验闭环

```text
首页待办卡
  → 查看检查准备事项
  → 到院导航 / 预约状态查询
  → 检查完成状态
  → 报告预计时间与出具通知
  → 报告入口
  → 复诊或人工服务引导
```

### 6.2 对话辅助流程

```text
患者提问
  → 识别为任务查询 / 流程问题 / 审核知识 / 人工请求 / 高风险表达
  → 调用受控业务接口或知识库
  → 返回任务卡、明确操作或固定安全提示
  → 必要时创建带上下文的人工工单
```

## 7. 业务规则

1. 所有患者业务查询必须在完成身份认证、机构隔离和就诊人授权后执行。
2. 对话模型不能直接写入预约、支付、病历、处方等核心业务数据；写操作必须经受控接口、业务规则和幂等校验。
3. 报告、病历、检查结果等敏感内容按最小必要原则展示，并记录访问审计。
4. 高风险关键词规则、人工转接规则和患者教育内容必须可配置、可审核、可版本追溯。
5. 业务接口失败时不得伪造状态；应告知暂时不可查询，并提供重试或人工入口。
6. 代办人操作必须展示当前就诊人身份，避免误操作到其他家庭成员。

## 8. 外部系统与数据需求

| 系统 | 首期所需数据/能力 |
| --- | --- |
| 身份认证与患者主索引 | 患者身份、代办授权、机构归属 |
| 预约/挂号系统 | 预约记录、状态、改约/取消能力、科室和院区信息 |
| HIS | 就诊记录、复诊计划、服务项目状态 |
| LIS/RIS/PACS | 检查检验项目、准备事项、预约与报告状态、报告入口 |
| 消息中心 | 小程序订阅消息、短信或 App 推送的发送与回执 |
| 工单/人工工作台 | 队列、接管、处理状态、服务评价和会话摘要 |
| 审核知识库 | 内容来源、版本、生效期、适用范围和审核人 |

## 9. 非功能需求

### 9.1 安全与隐私

- 实施机构、角色、患者及代办关系四层权限控制。
- 对敏感操作和敏感数据访问记录审计日志，支持追溯。
- 对话记录不应默认用于模型训练；如需使用，需先完成脱敏、授权和审批。
- 输出内容标注服务性质和适用边界，避免误导为诊疗建议。

### 9.2 可用性与适老化

- 首页主要待办使用大字体、清晰状态和单一主操作。
- 支持文本、语音输入和人工入口；不因未使用智能客服而阻断服务。
- 关键流程支持中断后恢复，保留已填写和已完成状态。

### 9.3 可运营性

- 配置常见问题、任务文案、人工队列、风险规则和知识内容，不依赖代码发布。
- 提供无答案问题、转人工率、接口失败率、任务完成率和满意度报表。

## 10. MVP 范围与验收标准

### 10.1 MVP 范围

首期仅建设“检查检验全流程服务”，包含：

1. 患者身份与就诊人切换。
2. 检查待办卡、准备事项、地点与预约时间展示。
3. 检查/报告状态查询与报告出具通知。
4. 流程型智能问答和审核知识问答。
5. 门诊服务中心、专科护士两类人工转接。
6. 转接上下文、访问审计、异常提示与服务评价。

### 10.2 验收标准

1. 已登录患者可在首页查看自身待进行检查及其准备事项。
2. 患者询问“报告什么时候出”时，系统返回真实报告状态或明确说明查询失败，不编造结果。
3. 患者转人工后，人工工作台可查看当前任务、会话摘要、任务编号及转接原因。
4. 命中高风险规则时，系统不输出诊断或治疗建议，并展示固定紧急提示与指定服务入口。
5. 同一患者切换不同就诊人时，页面与对话均明确显示当前服务对象。
6. 所有业务读取和写入均可关联到请求、身份、时间及结果的审计记录。

## 11. 成功指标

| 指标 | 建议观察方式 |
| --- | --- |
| 自助完成率 | 患者无需人工接管即完成检查准备、状态查询或报告获取的比例 |
| 人工转接率 | 按场景、原因和队列分析；不以单纯降低转接率为唯一目标 |
| 重复咨询率 | 同一任务在短期内重复提出相同问题的比例 |
| 任务完成时长 | 从收到待办到完成关键步骤的时间 |
| 接管效率 | 人工首次响应时间、一次解决率和患者重复描述次数 |
| 患者满意度 | 任务完成后的简短评价与投诉率 |
| 安全事件 | 高风险规则遗漏、越权访问、错误状态答复和接口失败情况 |

## 12. 待确认事项

1. 首发机构类型：综合医院、专科医院、基层医疗机构或互联网医院。
2. 首发院区已有的预约、检查、报告、工单和消息接口能力。
3. 高风险词规则、人工接管 SLA 与紧急情况的院内责任路径。
4. 报告展示、患者教育内容和代办授权的合规要求。
5. MVP 是否以检查检验闭环作为唯一首发场景。
