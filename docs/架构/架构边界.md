# 架构边界

<!-- 本文作用：定义模块之间、AI 与规则之间、患者服务与临床诊疗之间的边界，避免迁移过程中职责混乱。 -->

## 当前 MD 的作用

本文件用于判断某个需求应该放在哪个模块、是否允许自动化处理，以及什么情况下必须转人工或提示就医。它是医疗安全和工程边界的共同约束。

## 产品边界

系统定位是“患者端医疗服务助手”，不是“AI 医生”。

允许自动化支持的范围：

1. 就医流程咨询。
2. 预约、检查、报告、缴费等状态查询。
3. 医院审核过的检查准备和服务说明。
4. 非诊断式的信息收集。
5. 人工客服、护士、药师、患者关系部门的分流转接。

不允许自动化给出的内容：

1. 疾病诊断结论。
2. 处方、用药剂量和换药建议。
3. 治疗方案选择。
4. 检查报告的医学解释或风险定级。
5. 急危重症处置建议。

## 模块边界

| 边界 | 规则 |
| --- | --- |
| 前端与 AI 服务 | 前端负责展示和交互，不在前端写医疗判断规则 |
| AI 服务与业务系统 | AI 服务负责理解和编排，真实状态以业务系统返回为准 |
| LLM 与规则引擎 | 高风险、身份校验、操作确认必须走确定性规则 |
| 知识库与生成回答 | 医疗流程知识必须来自审核版本，LLM 只做表达组织 |
| 自动客服与人工客服 | 超出边界、权限不足、患者不满意时必须可转人工 |

## 风险边界

1. 出现胸痛、呼吸困难、意识障碍、大出血、自伤自杀等高风险表达时，直接进入急症提示和人工/急诊指引。
2. 患者要求解读检查结果时，只能说明“报告状态、获取路径、建议咨询医生”，不能解释异常指标代表什么。
3. 涉及儿童、孕产妇、老人、慢病用药时，默认提高风险等级。
4. 系统无法确认身份或授权时，不返回个人就诊信息。
