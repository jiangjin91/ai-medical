# 后续需求池

<!-- 本文作用：收集暂未进入当前迭代、但后续可能建设的能力。 -->

## 当前 MD 的作用

本文件用于沉淀未来方向，避免讨论过的想法丢失。进入开发前，需要从这里拆到 `当前迭代计划.md` 并补充设计文档。

## 候选能力

| 优先级 | 能力 | 说明 |
| --- | --- | --- |
| P1 | 复诊提醒 | 按医嘱或院内规则提醒复诊 |
| P1 | 检查准备个性化提醒 | 基于项目、时间、地点生成准备清单 |
| P1 | 院内导航 | 结合院区、楼栋、科室、检查地点 |
| P2 | 家属代办 | 授权后为老人、儿童等代办查询 |
| P2 | 满意度回访 | 对服务流程做轻量回访 |
| P2 | 多渠道接入 | 支持公众号、小程序、App、Web |
| P3 | 运营配置后台 | 让医院人员维护 FAQ、流程和转接规则 |

## 进入迭代条件

1. 有明确患者场景。
2. 有医院业务接口或可模拟数据。
3. 已定义安全边界。
4. 已定义验收标准。
